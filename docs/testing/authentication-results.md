# Test scenarios: Authentication-Results

Scenarios for the Authentication-Results parser (RFC 8601 §2.2) and for the header fields hallmark generates. Conventions are in [README.md](README.md).

Scenarios based on the examples in RFC 8601 Appendix B keep the structure of the example, with its domains moved under `.invalid`.

| ID | Level | Given | When | Then | Spec |
|----|-------|-------|------|------|------|
| ARH-001 | unit | `Authentication-Results: void.invalid 1; none`, after RFC 8601 Appendix B.2 | the field is parsed | the authserv-id `void.invalid`, the version `1`, and no results: no authentication was done | [HDR-009](../reference/requirements.md#header-parsing), [AR-003](../reference/requirements.md#authentication-results-rfc-8601), [RFC 8601 §2.2](https://www.rfc-editor.org/rfc/rfc8601.html#section-2.2) |
| ARH-002 | unit | `Authentication-Results: void.invalid;\r\n spf=pass smtp.mailfrom=sender.invalid`, after Appendix B.3 | the field is parsed | the authserv-id `void.invalid`, the version `1` because none is given, and one result: the method `spf`, the result `pass`, and the property `smtp.mailfrom` with the value `sender.invalid` | [HDR-009](../reference/requirements.md#header-parsing), [RFC 8601 §2.2](https://www.rfc-editor.org/rfc/rfc8601.html#section-2.2) |
| ARH-003 | unit | `Authentication-Results: void.invalid;\r\n auth=pass (cram-md5) smtp.auth=sender@sender.invalid;\r\n spf=pass smtp.mailfrom=sender.invalid`, after Appendix B.4 | the field is parsed | two results in order: `auth=pass` with the comment `cram-md5` and the property `smtp.auth`, then `spf=pass` with the property `smtp.mailfrom` | [HDR-009](../reference/requirements.md#header-parsing), [RFC 8601 §2.2](https://www.rfc-editor.org/rfc/rfc8601.html#section-2.2) |
| ARH-004 | unit | `Authentication-Results: foo.void.invalid (foobar) 1 (baz);\r\n dkim (Because I like it) / 1 (One yay) = (wait for it) fail\r\n policy (A dot can go here) . (like that) expired\r\n (this surprised me) = (as I wasn't expecting it) 1362471462`, after Appendix B.7 | the field is parsed | the authserv-id `foo.void.invalid`, the version `1`, and one result: the method `dkim` at method version `1`, the result `fail`, and the property `policy.expired` with the value `1362471462` | [HDR-009](../reference/requirements.md#header-parsing), [RFC 8601 §2.2](https://www.rfc-editor.org/rfc/rfc8601.html#section-2.2) |
| ARH-005 | unit | `Authentication-Results: void.invalid; dkim=fail reason="bad signature" header.d=void.invalid` | the field is parsed | the result `fail`, the reason `bad signature` taken from its quoted string, and the property `header.d` | [HDR-009](../reference/requirements.md#header-parsing), [RFC 8601 §2.2](https://www.rfc-editor.org/rfc/rfc8601.html#section-2.2), [RFC 2045 §5.1](https://www.rfc-editor.org/rfc/rfc2045.html#section-5.1) |
| ARH-006 | unit | `Authentication-Results: void.invalid; dkim2=pass header.d=signer.invalid` | the field is parsed | the method `dkim2`, the result `pass`, and the property `header.d` with the value `signer.invalid` | [HDR-009](../reference/requirements.md#header-parsing), [AR-004](../reference/requirements.md#authentication-results-rfc-8601), [authres-02 §3](https://datatracker.ietf.org/doc/html/draft-gondwana-dkim2-authres-02#section-3) |
| ARH-007 | unit | `Authentication-Results: void.invalid; spf`, with no result | the field is parsed | an error that names the methodspec rule at the end of the field, and no results | [HDR-009](../reference/requirements.md#header-parsing), [HDR-010](../reference/requirements.md#header-parsing), [RFC 8601 §2.2](https://www.rfc-editor.org/rfc/rfc8601.html#section-2.2) |
| ARH-008 | property | Any set of results that hallmark produces for one message | they are written as an Authentication-Results field and parsed back | the same authserv-id, methods, results, reasons and properties | [AR-001](../reference/requirements.md#authentication-results-rfc-8601), [HDR-009](../reference/requirements.md#header-parsing) |
| ARH-009 | fuzz | The Authentication-Results parser | it is fuzzed | it never panics, and every error names a rule and an offset | [SAF-001](../reference/requirements.md#hostile-input), [SAF-003](../reference/requirements.md#hostile-input) |
