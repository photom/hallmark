# Test scenarios: Running a check

Scenarios for driving a check: the order of input, questions and answers, errors from the caller's side, and the driver. Conventions are in [README.md](README.md).

| ID | Level | Given | When | Then | Spec |
|----|-------|-------|------|------|------|
| RUN-001 | unit | An SPF check for MAIL FROM `<a@void.invalid>` | the envelope is passed | the check lists the TXT question for `void.invalid` before any header field arrives | [CHK-001](../reference/requirements.md#running-a-check), [DNS-005](../reference/requirements.md#dns), [RFC 7208 §4.4](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.4) |
| RUN-002 | unit | A DKIM check of a message with one DKIM-Signature carrying `d=void.invalid` and `s=sel` | the header section ends | the check lists one question, TXT `sel._domainkey.void.invalid`, before any body chunk arrives | [CHK-001](../reference/requirements.md#running-a-check), [DNS-005](../reference/requirements.md#dns), [RFC 6376 §3.6.2.1](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.6.2.1) |
| RUN-003 | unit | A check whose input is complete, with one question still unanswered | the caller asks for the result | the check reports that it waits for that question and returns no result | [CHK-002](../reference/requirements.md#running-a-check) |
| RUN-004 | unit | An SPF check whose TXT question gets a temporary failure with the description `timeout` | the check finishes | `temperror`, and the trace records `timeout` as the resolver gave it | [CHK-002](../reference/requirements.md#running-a-check), [DNS-009](../reference/requirements.md#dns), [GEN-005](../reference/requirements.md#general), [RFC 7208 §4.4](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.4) |
| RUN-005 | unit | A DKIM check whose header section hasn't ended | a body chunk arrives | an error to the caller that names the input out of order. The check gives no protocol result for it | [CHK-004](../reference/requirements.md#running-a-check) |
| RUN-006 | unit | A check with one open question | an answer arrives with an identifier the check never issued | an error to the caller, and the open question stays open | [CHK-004](../reference/requirements.md#running-a-check), [DNS-007](../reference/requirements.md#dns) |
| RUN-007 | unit | A check whose question already has an answer | a second answer to the same question arrives | an error to the caller, and the check keeps the first answer | [CHK-004](../reference/requirements.md#running-a-check), [DNS-007](../reference/requirements.md#dns) |
| RUN-008 | unit | A DMARC check with SPF and DKIM in one call, and its snapshot | the answers are given all at once, then one at a time, then in reverse order | the three runs give the same results | [CHK-003](../reference/requirements.md#running-a-check), [GEN-001](../reference/requirements.md#general) |
| RUN-009 | unit | A message with two DKIM signatures that both carry `d=void.invalid` and `s=sel` | the header section ends | the check lists one key question, and both signature steps read its answer | [DNS-007](../reference/requirements.md#dns) |
| RUN-010 | unit | The SPF record `v=spf1 include:a.void.invalid include:a.void.invalid -all`, where `a.void.invalid` publishes `v=spf1 -all` | the check runs | one TXT question for `a.void.invalid`, a lookup count of 2, and `fail`: each `include` gets `fail` from the inner check, which doesn't match | [DNS-007](../reference/requirements.md#dns), [RFC 7208 §4.6.4](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.6.4), [RFC 7208 §5.2](https://www.rfc-editor.org/rfc/rfc7208.html#section-5.2) |
| RUN-011 | unit | The driver, with a test resolver that answers questions in the reverse order of asking | the driver runs the DMARC check of RUN-008 | the same results and trace as when the snapshot resolver answers in order | [CHK-005](../reference/requirements.md#running-a-check), [CHK-003](../reference/requirements.md#running-a-check) |
| RUN-012 | unit | The driver, built without any async runtime crate, and a minimal executor written in the test | the driver runs an SPF check to the end | the check finishes, and the build pulls in no async runtime | [CHK-005](../reference/requirements.md#running-a-check), [DNS-003](../reference/requirements.md#dns) |
