# Test scenarios: Running a check

Scenarios for driving a check: the order of input, questions and answers, errors from the caller's side, and the driver. Conventions are in [README.md](README.md).

| ID | Level | Given | When | Then | Spec |
|----|-------|-------|------|------|------|
| RUN-001 | unit | An SPF check for MAIL FROM `<a@void.test>` | the envelope is passed | the check lists the TXT question for `void.test` before any header field arrives | [CHK-001](../reference/requirements.md#running-a-check), [DNS-005](../reference/requirements.md#dns), [RFC 7208 §4.4](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.4) |
| RUN-002 | unit | A DKIM check of a message with one DKIM-Signature carrying `d=void.test` and `s=sel` | the header section ends | the check lists one question, TXT `sel._domainkey.void.test`, before any body chunk arrives | [CHK-001](../reference/requirements.md#running-a-check), [DNS-005](../reference/requirements.md#dns), [RFC 6376 §3.6.2.1](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.6.2.1) |
| RUN-003 | unit | A check whose input is complete, with one question still unanswered | the caller asks for the result | the check reports that it waits for that question and returns no result | [CHK-002](../reference/requirements.md#running-a-check) |
| RUN-004 | unit | An SPF check whose TXT question gets a temporary failure with the description `timeout` | the check finishes | `temperror`, and the trace records `timeout` as the resolver gave it | [CHK-002](../reference/requirements.md#running-a-check), [DNS-009](../reference/requirements.md#dns), [GEN-005](../reference/requirements.md#general), [RFC 7208 §4.4](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.4) |
| RUN-005 | unit | A DKIM check whose header section hasn't ended | a body chunk arrives | an error to the caller that names the input out of order. The check gives no protocol result for it | [CHK-004](../reference/requirements.md#running-a-check) |
| RUN-006 | unit | A check with one open question | an answer arrives with an identifier the check never issued | an error to the caller, and the open question stays open | [CHK-004](../reference/requirements.md#running-a-check), [DNS-007](../reference/requirements.md#dns) |
| RUN-007 | unit | A check whose question already has an answer | a second answer to the same question arrives | an error to the caller, and the check keeps the first answer | [CHK-004](../reference/requirements.md#running-a-check), [DNS-007](../reference/requirements.md#dns) |
| RUN-008 | unit | A DMARC check with SPF and DKIM in one call, and its snapshot | the answers are given all at once, then one at a time, then in reverse order | the three runs give the same results | [CHK-003](../reference/requirements.md#running-a-check), [GEN-001](../reference/requirements.md#general) |
| RUN-009 | unit | A message with two DKIM signatures that both carry `d=void.test` and `s=sel` | the header section ends | the check lists one key question, and both signature steps read its answer | [DNS-007](../reference/requirements.md#dns) |
| RUN-010 | unit | The SPF record `v=spf1 include:a.void.test include:a.void.test -all`, where `a.void.test` publishes `v=spf1 -all` | the check runs | one TXT question for `a.void.test`, a lookup count of 2, and `fail`: each `include` gets `fail` from the inner check, which doesn't match | [DNS-007](../reference/requirements.md#dns), [RFC 7208 §4.6.4](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.6.4), [RFC 7208 §5.2](https://www.rfc-editor.org/rfc/rfc7208.html#section-5.2) |
| RUN-011 | unit | The driver, with a test resolver that answers questions in the reverse order of asking | the driver runs the DMARC check of RUN-008 | the same results and trace as when the snapshot resolver answers in order | [CHK-005](../reference/requirements.md#running-a-check), [CHK-003](../reference/requirements.md#running-a-check) |
| RUN-012 | unit | The driver, built without any async runtime crate, and a minimal executor written in the test | the driver runs an SPF check to the end | the check finishes, and the build pulls in no async runtime | [CHK-005](../reference/requirements.md#running-a-check), [DNS-003](../reference/requirements.md#dns) |
| RUN-013 | unit | A DKIM check of a message with one DKIM-Signature carrying `c=simple/simple`, and an empty body | the end of the message follows the end of the header section, with no body chunk between them | the check accepts the order and gives the caller no error. Once the key answer arrives, it finishes, and its trace records the hash of the empty body, `frcCV1k9oG9oKj3dpUqdJg1PxRT2RSN/XKdLCPjaYaY=` (CAN-001) | [CHK-001](../reference/requirements.md#running-a-check), [RFC 6376 §3.4.3](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.4.3) |
| RUN-014 | unit | A DMARC check in RFC 7489 mode with SPF and DKIM, MAIL FROM `<b@mail.void.test>`, `From: a@void.test` and a DKIM signature with `d=void.test` | the envelope is passed, then the header section ends | after the envelope, the check lists the public suffix question for `mail.void.test` next to the TXT question for the same name. After the header section, it lists one more public suffix question, for `void.test`, which the author domain and `d=` share | [CHK-001](../reference/requirements.md#running-a-check), [DMC-010](../reference/requirements.md#dmarc), [DNS-005](../reference/requirements.md#dns) |
| RUN-015 | unit | The driver, a test resolver, and a test source of public suffixes that counts its calls | the driver runs the check of RUN-014 to the end | the source gets each public suffix question once, and the result and sorted trace equal those of a run in which the test answers every question itself | [CHK-005](../reference/requirements.md#running-a-check), [DMC-010](../reference/requirements.md#dmarc) |
| RUN-016 | unit | A message with one DKIM-Signature, and its snapshot | the message is checked three times: with `whole_message`; with `header_section`, body chunks and `end_of_message`; and with `header_field` for each field, `end_of_header_fields`, body chunks and `end_of_message` | the three runs give the same results | [GEN-003](../reference/requirements.md#general), [STR-008](../reference/requirements.md#streaming), [CHK-001](../reference/requirements.md#running-a-check) |
| RUN-017 | unit | Options made with `Options::new` and the kind `Dmarc`, with no mode set, `dmarc_spf` and `dmarc_dkim` set to `Absent`, and `From: a@void.test` | DMARC runs | the event `[5]` `dmarc` has the mode `rfc9989` | [DMC-001](../reference/requirements.md#dmarc), [RFC 9989 §4.10](https://www.rfc-editor.org/rfc/rfc9989.html#section-4.10) |
| RUN-018 | unit | A message with three DKIM-Signature fields, with `c=simple/simple`, `c=relaxed/relaxed`, and `c=relaxed/relaxed` with `l=10`, and a body of 100 lines | the test passes the body once, in chunks of 7 bytes, and overwrites the buffer of each chunk as soon as the call that passed it returns | each body hash equals the one that its mode and `l=` give for the whole body in one chunk: the check reads each chunk once, during the call that passes it | [STR-010](../reference/requirements.md#streaming), [STR-007](../reference/requirements.md#streaming), [STR-001](../reference/requirements.md#streaming) |
