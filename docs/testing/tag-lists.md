# Test scenarios: Tag lists

Scenarios for the tag=value list parser that DKIM and DKIM2 share (RFC 6376 §3.2, draft-09 §8), and for the decoders of tag values. Conventions are in [README.md](README.md).

The parser gets a header field value or the text of a DNS record, with any folding as it arrived.

## Tag lists

| ID | Level | Given | When | Then | Spec |
|----|-------|-------|------|------|------|
| TAG-001 | unit | `v=1; a=rsa-sha256` | the list is parsed | two tags: `v` with the value `1`, and `a` with `rsa-sha256` | [HDR-006](../reference/requirements.md#header-parsing), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2) |
| TAG-002 | unit | ` a = x y ;  b=z;` | the list is parsed | `a` is `x y` and `b` is `z`: the white space around a tag and before `;` isn't part of its value, the space inside `x y` is, and the grammar allows the final `;` | [HDR-006](../reference/requirements.md#header-parsing), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2), [draft-09 §8](https://datatracker.ietf.org/doc/html/draft-ietf-dkim-dkim2-spec-09#section-8) |
| TAG-003 | unit | `a=1; a=2` | the list is parsed | the whole list is invalid, and the error names the duplicate tag `a` | [HDR-006](../reference/requirements.md#header-parsing), [HDR-010](../reference/requirements.md#header-parsing), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2), [draft-09 §8](https://datatracker.ietf.org/doc/html/draft-ietf-dkim-dkim2-spec-09#section-8) |
| TAG-004 | unit | A DKIM-Signature that holds every required tag and also `zz=9` | the signature's tags are read | the list is valid, and DKIM ignores `zz` | [HDR-006](../reference/requirements.md#header-parsing), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2) |
| TAG-005 | unit | `a=; b=1` | the list is parsed | `a` is present with an empty value, which differs from an omitted tag | [HDR-006](../reference/requirements.md#header-parsing), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2) |
| TAG-006 | unit | A DKIM-Signature that holds every required tag, except that its version is written `V=1` | the signature's tags are read | the list holds a tag named `V`, not `v`, so the signature lacks the required `v=` and gets PERMFAIL (signature missing required tag) | [HDR-006](../reference/requirements.md#header-parsing), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2), [RFC 6376 §6.1.1](https://www.rfc-editor.org/rfc/rfc6376.html#section-6.1.1) |
| TAG-007 | unit | `1a=x` | the list is parsed | the list is invalid, and the error names the tag-name rule at offset 0: a tag name starts with a letter | [HDR-006](../reference/requirements.md#header-parsing), [HDR-010](../reference/requirements.md#header-parsing), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2) |
| TAG-008 | unit | A DKIM-Signature with `d=例え.invalid`, in UTF-8, in a message with internationalized header fields | the signature's tags are read | the list is valid, and `d` holds `例え.invalid` | [HDR-006](../reference/requirements.md#header-parsing), [RFC 8616 §5](https://www.rfc-editor.org/rfc/rfc8616.html#section-5), [RFC 6376 §3.2](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.2) |
| TAG-009 | unit | A DKIM2-Signature with `i=1` that has every required tag, and whose `d=` holds `例え.invalid` in UTF-8 | the field is read | PERMERROR, with the string `PERMERROR: DKIM2-Signature i=1 syntax error`: DKIM2 tag values are ASCII | [HDR-006](../reference/requirements.md#header-parsing), [DK2-013](../reference/requirements.md#dkim2), [draft-09 §8](https://datatracker.ietf.org/doc/html/draft-ietf-dkim-dkim2-spec-09#section-8), [draft-09 §14.2](https://datatracker.ietf.org/doc/html/draft-ietf-dkim-dkim2-spec-09#section-14.2) |

|----|-------|-------|------|------|------|
| TAG-020 | unit | `bh=frcCV1k9oG9oKj3dpUqdJg1P\r\n xRT2RSN/XKdLCPjaYaY=`, folded inside the base64 | the `bh=` value is decoded | the 32-byte SHA-256 hash of `\r\n`, the same as for the unfolded value `frcCV1k9oG9oKj3dpUqdJg1PxRT2RSN/XKdLCPjaYaY=` | [HDR-007](../reference/requirements.md#header-parsing), [RFC 6376 §2.10](https://www.rfc-editor.org/rfc/rfc6376.html#section-2.10), [RFC 6376 §3.5](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.5) |

| TAG-022 | unit | `z=Subject:a=3bb`, with a lowercase hex digit | the `z=` value is decoded | an error: dkim-quoted-printable allows only uppercase hex digits | [HDR-007](../reference/requirements.md#header-parsing), [HDR-010](../reference/requirements.md#header-parsing), [RFC 6376 §2.11](https://www.rfc-editor.org/rfc/rfc6376.html#section-2.11) |
| TAG-023 | unit | `h=From : To:\r\n Subject` | the `h=` value is decoded | the names `From`, `To` and `Subject`: the folding white space around the colons isn't part of them | [HDR-007](../reference/requirements.md#header-parsing), [RFC 6376 §3.5](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.5) |
| TAG-024 | unit | `z=Subject:café`, with `é` unencoded in UTF-8, in a message with internationalized header fields | the `z=` value is decoded | the copied header field `Subject:café` | [HDR-007](../reference/requirements.md#header-parsing), [RFC 8616 §5](https://www.rfc-editor.org/rfc/rfc8616.html#section-5) |
| TAG-025 | unit | A `z=` value holding the byte 0xFF, which can't occur in UTF-8 | the `z=` value is decoded | an error: the byte is neither a dkim-safe-char nor part of a well-formed UTF-8 character | [HDR-007](../reference/requirements.md#header-parsing), [HDR-010](../reference/requirements.md#header-parsing), [RFC 8616 §5](https://www.rfc-editor.org/rfc/rfc8616.html#section-5), [RFC 3629 §4](https://www.rfc-editor.org/rfc/rfc3629.html#section-4) |
| TAG-026 | unit | A DKIM-Signature with `c=relaxed` | the `c=` value is decoded | `relaxed` for the header and `simple` for the body | [HDR-007](../reference/requirements.md#header-parsing), [RFC 6376 §3.5](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.5) |
| TAG-027 | unit | A DKIM-Signature with no `c=` tag | the signature's tags are read | `simple` for the header and `simple` for the body | [HDR-007](../reference/requirements.md#header-parsing), [RFC 6376 §3.5](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.5) |
| TAG-028 | unit | A DKIM-Signature with a 13-digit `t=` | the `t=` value is decoded | an infinite timestamp, which lies in the future of any verification time, with no overflow | [HDR-013](../reference/requirements.md#header-parsing), [RFC 6376 §3.5](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.5) |
| TAG-029 | unit | A DKIM-Signature with a 13-digit `x=` | the `x=` value is decoded | an infinite expiration time, so the signature never expires, with no overflow | [HDR-013](../reference/requirements.md#header-parsing), [RFC 6376 §3.5](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.5) |
| TAG-030 | unit | A DKIM-Signature whose `l=` has 76 digits, too many for the parser's integer | the `l=` value is decoded | a body length larger than any body, so the whole body is hashed, with no overflow | [HDR-013](../reference/requirements.md#header-parsing), [ADR 0010](../adr/0010-a-dkim-l-tag-larger-than-the-body-gets-no-special-rule.md), [RFC 6376 §3.5](https://www.rfc-editor.org/rfc/rfc6376.html#section-3.5) |
