# Test scenarios: Parsers

Scenarios for the rules that every parser shares: errors, byte ranges, numbers, limits and nesting. Each parser's own grammar has scenarios in the file for its area. Conventions are in [README.md](README.md).

| ID | Level | Given | When | Then | Spec |
|----|-------|-------|------|------|------|
| PRS-001 | unit | The pasted record line `void.invalid. IN TXT "v=spf1 -all`, whose quoted string has no closing quote | the line is parsed | an error that names the character-string rule, line 1, and the offset where the line ends. No record is returned | [PAR-001](../reference/requirements.md#parsers), [DNS-010](../reference/requirements.md#dns), [RFC 1035 §5.1](https://www.rfc-editor.org/rfc/rfc1035.html#section-5.1) |
| PRS-002 | unit | The SPF record `v=spf1 ip4:192.0.2.0/33 -all` | the record is evaluated | `permerror`, and the error names the ip4-cidr-length rule at the offset of `/33`: the length lies outside 0 to 32 | [PAR-001](../reference/requirements.md#parsers), [PAR-003](../reference/requirements.md#parsers), [RFC 7208 §5.6](https://www.rfc-editor.org/rfc/rfc7208.html#section-5.6), [RFC 7208 §4.6](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.6) |
| PRS-003 | unit | A DKIM-Signature field whose `d=` value, `void.invalid`, starts at byte 42 of the raw field | the field is parsed and verified with the full trace | the value carries the byte range from 42 up to 54 of the raw field, and the trace step that reads `d=` points at that range | [PAR-002](../reference/requirements.md#parsers), [HDR-001](../reference/requirements.md#header-parsing) |
| PRS-004 | unit | A caller that lowers the header field limit to 5 for one call, and a message with 6 header fields | the message is checked in that call, then again with the default limits | the first call gives each check its error result and a trace step that names the limit. The second call reads all 6 fields | [PAR-004](../reference/requirements.md#parsers), [SAF-002](../reference/requirements.md#hostile-input) |
| PRS-005 | property | DKIM2 recipe JSON with arrays nested to any depth up to the size limit | the recipe is parsed | below the depth limit it parses or fails on its schema. At the limit it fails with an error that names the depth limit. No depth makes the parser recurse or panic | [PAR-005](../reference/requirements.md#parsers), [SAF-001](../reference/requirements.md#hostile-input), [SAF-002](../reference/requirements.md#hostile-input), [draft-09 §5](https://datatracker.ietf.org/doc/html/draft-ietf-dkim-dkim2-spec-09#section-5) |
