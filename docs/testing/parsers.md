# Test scenarios: Parsers

Scenarios for the rules that every parser shares: errors, byte ranges, numbers, limits and nesting. Each parser's own grammar has scenarios in the file for its area. Conventions are in [README.md](README.md).

| ID | Level | Given | When | Then | Spec |
|----|-------|-------|------|------|------|
| PRS-001 | unit | The pasted record line `void.test. IN TXT "v=spf1 -all`, whose quoted string has no closing quote | the line is parsed | an error that names the character-string rule, line 1, and the offset where the line ends. No record is returned | [PAR-001](../reference/requirements.md#parsers), [DNS-010](../reference/requirements.md#dns), [RFC 1035 §5.1](https://www.rfc-editor.org/rfc/rfc1035.html#section-5.1) |
| PRS-002 | unit | The SPF record `v=spf1 ip4:192.0.2.0/33 -all` | the record is evaluated | `permerror`, and the error names the ip4-cidr-length rule at the offset of `/33`: the length lies outside 0 to 32 | [PAR-001](../reference/requirements.md#parsers), [PAR-003](../reference/requirements.md#parsers), [RFC 7208 §5.6](https://www.rfc-editor.org/rfc/rfc7208.html#section-5.6), [RFC 7208 §4.6](https://www.rfc-editor.org/rfc/rfc7208.html#section-4.6) |
| PRS-003 | unit | A DKIM-Signature field whose `d=` value, `void.test`, starts at byte 42 of the raw field | the field is parsed and verified with the full trace | the value carries the byte range from 42 up to 51 of the raw field, and the trace step that reads `d=` points at that range | [PAR-002](../reference/requirements.md#parsers), [HDR-001](../reference/requirements.md#header-parsing) |
| PRS-004 | unit | A verifying caller that lowers the header field limit to 5 for one call, and a message with 6 header fields | the message is checked in that call, then again with the default limits | the first call gives each check its error result and a trace step that names the limit. The second call reads all 6 fields | [PAR-004](../reference/requirements.md#parsers), [SAF-002](../reference/requirements.md#hostile-input) |
| PRS-005 | property | DKIM2 recipe JSON with arrays nested to any depth up to the size limit | the recipe is parsed | below the depth limit it parses or fails on its schema. At the limit it fails with an error that names the depth limit. No depth makes the parser recurse or panic | [PAR-005](../reference/requirements.md#parsers), [SAF-001](../reference/requirements.md#hostile-input), [SAF-002](../reference/requirements.md#hostile-input), [draft-09 §5](https://datatracker.ietf.org/doc/html/draft-ietf-dkim-dkim2-spec-09#section-5) |
| PRS-006 | unit | Nothing | every field of `Limits::default()` and `DocumentLimits::default()` is read, and `Limit::name` gives the name of each limit | each value is the default and each name the limit's name that [Limits](../reference/design/limits.md) gives, `driver_in_flight` included | [PAR-004](../reference/requirements.md#parsers), [SAF-002](../reference/requirements.md#hostile-input) |
| PRS-007 | unit | The JSON text ` {"a":[1,-0.5e+3,true,false,null],"b":{},"c":"x"}\r\n`, with white space before and after it | the JSON reader reads it | an object with the members `a`, `b` and `c` in that order. The numbers keep their text, `1` and `-0.5e+3` | [PAR-001](../reference/requirements.md#parsers), [RFC 8259 §2](https://www.rfc-editor.org/rfc/rfc8259.html#section-2), [RFC 8259 §4](https://www.rfc-editor.org/rfc/rfc8259.html#section-4), [RFC 8259 §6](https://www.rfc-editor.org/rfc/rfc8259.html#section-6) |
| PRS-008 | unit | A JSON string that holds the eight two-character escapes, the six-character escape of U+00E9 in lowercase hex digits, and the 12-character escape of U+1F600 (surrogates D83D and DE00) in uppercase hex digits. Then nine strings, each between quotation marks: the escape of the low surrogate DEAD alone, the escape of the high surrogate D83D followed by `x`, the escape of D83D followed by the escape of U+0041, the escape of the noncharacter U+FFFF, the bytes EF BF BF, a backslash followed by `a`, a backslash and `u` followed by only `12`, the bytes `a` 1F `b`, and the byte FF | the JSON reader reads each | the first gives `"\/`, BS, FF, LF, CR, HT, `é` and U+1F600. The nine others give an error at offset 1, 1, 1, 1, 1, 2, 5, 2 and 1: an unpaired surrogate, a high surrogate with no low one (twice), an escaped noncharacter, a noncharacter in UTF-8, an unknown escape, an escape with too few hex digits, an unescaped control character, and a byte that isn't UTF-8 | [PAR-001](../reference/requirements.md#parsers), [RFC 8259 §7](https://www.rfc-editor.org/rfc/rfc8259.html#section-7), [RFC 7493 §2.1](https://www.rfc-editor.org/rfc/rfc7493.html#section-2.1) |
| PRS-009 | unit | The JSON text `{"a":1,"a":2}`, then the same text with the second name written as the six-character escape of U+0061, then `{"a":{"a":1}}` | the JSON reader reads each | the first two give an error at offset 7, where the repeated name starts: two names are the same once their escapes are decoded. The third reads, because its two `a` members are in different objects | [PAR-001](../reference/requirements.md#parsers), [RFC 7493 §2.3](https://www.rfc-editor.org/rfc/rfc7493.html#section-2.3) |
| PRS-010 | unit | The JSON texts `01`, `1.`, `-`, `1e+`, `[1,]`, `tru`, `{"a" 1}`, `{"a":1} x`, nothing at all, and `{}` after the byte order mark EF BB BF | the JSON reader reads each | an error at offset 1, 2, 1, 3, 3, 0, 5, 8, 0 and 0. The reader repairs nothing and skips nothing but white space | [PAR-001](../reference/requirements.md#parsers), [RFC 8259 §2](https://www.rfc-editor.org/rfc/rfc8259.html#section-2), [RFC 8259 §6](https://www.rfc-editor.org/rfc/rfc8259.html#section-6), [RFC 8259 §8.1](https://www.rfc-editor.org/rfc/rfc8259.html#section-8.1) |
| PRS-011 | unit | Arrays nested 16 levels, then 17 levels, then 100,000 levels, each read with a depth limit of 16 | the JSON reader reads each | the first reads. The second and the third give a depth error at offset 16, where the seventeenth array opens. No depth makes the reader recurse or overflow its stack | [PAR-005](../reference/requirements.md#parsers), [SAF-001](../reference/requirements.md#hostile-input), [SAF-002](../reference/requirements.md#hostile-input) |
| PRS-012 | unit | Three traces: one whose first record holds an LF inside its JSON text, as white space between two members; one whose first record starts with two RS bytes; and one whose last record has no LF after its JSON text | `sort_trace` sorts each | `trace.record_malformed` at the offset just after the inner LF, at offset 0, and at the offset of the last record's RS. A record of a trace is RS, bytes with no RS or LF, and LF, so the first record ends at the inner LF and the bytes after it don't start with RS. RFC 7464 §2.1 lets a parser ignore the second RS, but a trace has one RS before each record | [PAR-001](../reference/requirements.md#parsers), [TRC-007](../reference/requirements.md#trace-and-reasoning), [Trace format](../reference/trace-format.md#records), [RFC 7464 §2.1](https://www.rfc-editor.org/rfc/rfc7464.html#section-2.1) |
